# Promotion Notes

This is a modest promotion plan for Книжница. The goal is to find real writers
and maintainers who may care about a local-first writing tool. Do not spam, buy
stars, ask uninterested people for stars, or invent adoption numbers.

## Principles

- Be clear that the project is new.
- Ask for feedback first, not praise.
- Use fake demo text in screenshots and examples.
- Mention that the app is local-first: no accounts, no cloud, manuscripts stay
  on the user's computer.
- Ask for a GitHub star only if the person finds the project useful or wants to
  follow its development.

## Places To Share

- GitHub profile: add a short pinned note or profile README link.
- X/Twitter: share a short post with screenshot, release link, and local-first
  privacy angle.
- Reddit / writing communities: only post where self-promotion is allowed; focus
  on asking for feedback from writers.
- Русскоязычные сообщества писателей: рассказать простым языком, что это
  локальная программа для черновиков и структуры книги.
- Telegram/Discord-чаты для авторов: делиться только там, где это уместно и не
  выглядит как спам.
- Product Hunt / Hacker News Show HN: consider this after the English README,
  release, and screenshots are polished enough for an English-speaking audience.
- Personal writer/tester contacts: ask a few real writers to try the app with
  fake or non-sensitive drafts first.

## Short English Post

I open-sourced Knizhnitsa, a local-first Windows desktop app for writers. It
helps manage books, chapters, characters, plans, search, trash, backups, and
DOCX/TXT export.

The privacy promise is simple: no cloud, no accounts, manuscripts stay on your
computer.

GitHub: https://github.com/ryzhkevichpavel-del/knizhnitsa

If the project is useful to you or you want to follow its development, a GitHub
star is appreciated. Feedback from writers is even more useful: what feels good,
what is missing, and where the app should be safer.

## Follow-up

Track real interest through GitHub stars, release downloads, issues, feedback,
and pull requests. Do not treat vanity numbers as proof that the app is safe or
finished.
